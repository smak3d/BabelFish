# BabelFish

Офлайн-переводчик речи: клиент записывает звук и отправляет на сервер, сервер
распознавалкой **whisper.cpp** превращает его в текст, а LLM **llama.cpp**
возвращает ответ. Всё локально, ни один байт наружу не уходит.

```
┌────────────┐   ZeroMQ/TCP   ┌──────────────────────────────┐
│  Клиент    │  аудио/текст   │           Сервер             │
│  запись    │ ─────────────► │  whisper (RTX 2070)  → текст │
│  и вывод   │ ◄───────────── │  llama  (RTX 5070 Ti) → ответ│
└────────────┘     ответ      └──────────────────────────────┘
```

## Структура

| Каталог | Что внутри |
| --- | --- |
| `client/` | Запись звука (PortAudio), ввод с клавиатуры, цепочка состояний, отправка на сервер |
| `server/` | ZeroMQ-сервер, транскрибация, лLM-ассистент |
| `shared/` | Протокол и обвязка — **контракт** между клиентом и сервером |
| `tests/` | Юнит-тесты протокола и конвейера |

Зависимости подтягиваются как git-сабмодули: `portaudio`, `whisper.cpp`,
`llama.cpp`. При первом клонировании — с флагом:

```powershell
git clone --recurse-submodules https://github.com/smak3d/BabelFish.git
```

Если уже клонировал без сабмодулей: `git submodule update --init --recursive`.

## Сборка

Нужен CMake ≥ 3.20 и компилятор с поддержкой C++20.

```powershell
cmake -S . -B build
cmake --build build --parallel
ctest --test-dir build --output-on-failure
```

Это даёт **CPU-вариант** — работает везде, медленно, но проверяемо.

### Сборка с CUDA

Для реальной работы нужен GPU-бэкенд. На Windows это отдельное дерево, потому
что **nvcc не работает с MinGW** — CUDA-версию собирают MSVC:

```powershell
.\build-cuda.bat
```

Скрипт сам поднимает окружение MSVC, добавляет nvcc в PATH, конфигурирует
дерево `build-cuda/` и копирует runtime-DLL рядом с exe. Требуется:

- Visual Studio Build Tools 2022 ( workload `VCTools`)
- CUDA Toolkit 13.4
- Включённая опция `BABELFISH_WITH_CUDA=ON` (скрипт ставит сам)

Обычная (CPU) сборка в `build/` при этом **не удаляется** — остаётся как
фолбэк, если с CUDA что-то пойдёт не так.

## Модели

Модели в репозитории не лежат (это гигабайты) — положи их сам и укажи пути.

По умолчанию сервер ищет:

| Назначение | Путь по умолчанию |
| --- | --- |
| Распознавание речи | `H:/models/ggml-large-v3-turbo.bin` |
| Ответы LLM (GGUF) | `H:/models/Qwen3-4B-Q6_K.gguf` |

Пути и устройства задаются опциями командной строки — см. `server/README.md`.

## Запуск

Порядок важен: сначала сервер, потом клиент.

```powershell
# терминал 1 — сервер
.\build-cuda\server\BabelFishServer.exe

# терминал 2 — клиент
.\build\client\BabelFishClient.exe
```

Для запуска клиента с другой машины укажи хост сервера:

```powershell
BabelFishClient.exe 192.168.3.136
```

На серверной машине понадобится разрешение входящего TCP-порта 5555 в
брандмауэре.

## Протокол

ZeroMQ поверх TCP, порт по умолчанию **5555**. Байтовый формат описан в
`shared/protocol/` — заголовок, тип сообщения и полезная нагрузка, всё в
little-endian. Клиент и сервер обязаны использовать **одну и ту же** версию
`shared/`: любое изменение в этом каталоге требует синхронизации обеих сторон
до запуска.

Подробности — в `client/README.md` и `server/README.md`.

## Тесты

```powershell
ctest --test-dir build --output-on-failure
```

| Тест | Что проверяет |
| --- | --- |
| `ProtocolRoundTrip` | Сериализация/десериализация сообщений |
| `TransportEcho` | Обмен через ZeroMQ |
| `InputPackaging` | Упаковка ввода |
| `PipelineFlow` | Конвейер целиком, **без загрузки моделей** |

Последний тест намеренно работает в ленивом режиме: модели не нужны, чтобы
проверка конвейера не занимала минуты и не требовала GPU.

## Производительность

Замеры на Ryzen 5 7500F + RTX 5070 Ti 16 ГБ + RTX 2070 8 ГБ:

| Операция | Скорость |
| --- | --- |
| LLM: prompt (Qwen3-4B Q6_K, 5070 Ti) | ~5500 токенов/с |
| LLM: генерация | ~127 токенов/с |
| Whisper large-v3-turbo: encode 30 с аудио (2070) | ~110 мс |

Раскладка по картам сделана намеренно: whisper на слабой карте, LLM на
сильной — они работают параллельно и не мешают друг другу.
